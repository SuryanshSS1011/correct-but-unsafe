# GPU confirmation, 14 November 2026

This file reports the first run of the kit in `gpu/`. It ran on Modal with
`modal run gpu/modal_app.py`, on an NVIDIA A100-SXM4-40GB with torch 2.15.0 and
Triton 3.9.0. Each kernel ran in its own container, and each repeat in a fresh
process. The raw files are `results/raw/gpu_minimal.json`,
`gpu_confirmation.json` and `gpu_crash_check.json`, which are not tracked.
`docs/DECISIONS.md` states what follows from them.

## 1. Minimal demonstration

`gpu/minimal_repro.py` launches one autotuned kernel with a grid fixed for a
block of 1024, at four sizes, in five fresh processes.

| n | Winner block in repeats 0 to 4 | Unwritten per later call |
|---|---|---|
| 8,192 | 256, 1024, 1024, 512, 2048 | 6,144 or 4,096 when the block is below 1024, else 0 |
| 65,536 | 256, 256, 256, 256, 1024 | 49,152 when the block is 256 |
| 1,048,576 | 256 in all five | 786,432 |
| 16,777,216 | 256 in all five | 12,582,912 |

A partial config won in 17 of 20 cells. The first call always left 0 elements
unwritten, and every later call left exactly the fraction the block size
predicts. The harness-style trials with `torch.empty` failed in all 17 cells
and passed in the other 3.

## 2. The 34 flagged Dr. Kernel kernels

Each kernel ran KernelGYM's five trials in training and eval mode, with and
without the poison fill, three times each, plus three marker tests per mode.

| Outcome | Kernels |
|---|---|
| Uninitialized-output kernels with unwritten elements under the poison fill | 19 of 29 |
| Poison-fill runs of those 29 kernels with unwritten elements | 76 of 174 |
| Kernels that showed the pass, fail, fail, fail, fail signature in some run | 17 |
| Kernels whose autotune winner changed between fresh processes | 16 |
| Kernels whose output returned the 1027 marker from a freed block | 18 |
| Kernels with unwritten elements under the poison fill whose plain trials all passed | 7 |
| Out-of-bounds kernels that faulted | 1 of 5 |

**Stale memory hides the defect.** For `984_r2`, `1586_r2`, `2118_r3`,
`3008_r2`, `5239_r2`, `6852_r1` and `7520_r1` the poison fill shows unwritten
elements and every plain trial passes. Three of them, `2118_r3`, `6852_r1` and
`7520_r1`, record no autotune winner and leave elements unwritten in all six
poison-fill runs. Their partial write is deterministic, and only the
allocator's stale memory makes it pass.

**The winner varies between processes.** `703_r1`, `984_r2`, `1915_r3`,
`2487_r3`, `5338_r2` and `7912_r3` pass all five trials in some processes and
show the 1-of-5 signature in others, with the same code and inputs.

**Not confirmed on this GPU.** No unwritten element appeared for `1695_r2`,
`1797_r3`, `3278_r2`, `3828_r2`, `4314_r4`, `6993_r1`, `7485_r3`, `8614_r4` and
`8853_r2`. Each is autotuned, and a covering config won in all twelve replay
processes. `4191_r4` leaves no element unwritten but returns the marker in all
six marker tests, which fits its census class of an uninitialized source read.
`3278_r2` fails 1 of 5 under the poison fill without any unwritten output
element, which suggests the poison reaches an intermediate buffer. It has not
been read yet.

**Out-of-bounds reads.** `7350_r1` raised an illegal memory access in all 18
runs. `160_r2`, `256_r1`, `825_r3` and `6135_r2` ran clean and correct. An
out-of-bounds read that lands inside another allocation does not fault on a
GPU, which is why the census relies on the bounds oracle.

## 3. Four kernels that crashed in KernelGYM

`236_r3`, `481_r3`, `3725_r4` and `6133_r2` ran with `CUDA_LAUNCH_BLOCKING=1`,
in both modes, with and without the poison fill. All runs completed, all
trials matched the reference and no marker returned. The illegal memory
accesses that KernelGYM recorded for them therefore did not come from these
kernels on this GPU. The likely cause is a CUDA error carried over from
another kernel in the same worker.

## 4. Smoke test on a T4

Before the full run, `984_r2` ran once on a Tesla T4. The autotuner chose
configs 3 and 4, which cover the output, and no element was left unwritten.
The raw file is `results/raw/t4-smoke/gpu_confirmation.json`.
