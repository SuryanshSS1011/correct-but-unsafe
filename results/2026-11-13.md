## 2. Sweep of every TritonGym reference at the fixed commit

Run 43382558336 covered 122 reference ops in seven of eight shards. 101 ran on
the CPU interpreter. Eleven ops outside the 13 known ones were flagged. Every
flag was triaged by reading the source.

| Op | Class | Detectors | Root cause |
|---|---|---|---|
| `embedding` | Out-of-bounds read | asan, tilelens, perturb | The wrapper draws ids from `torch.randint(10, 1000, ...)` against a weight table with 500 rows. |
| `index_select_cat` | Out-of-bounds read | asan, tilelens, perturb | The wrapper hard-codes the index `[0, 2, 4, 6, 8]` against sources with 5 rows. |
| `token_attn_llama2` | Out-of-bounds read and write | plain SIGSEGV, asan | `B_Loc` values up to `max_input_len` are multiplied by the batch stride of `K`, which has only `batch` entries on that axis. The output offset uses `att_out.stride(0)` and `stride(1)` as head and position strides, so writes reach element 1,376 of a 256-element output at the first test shape. |
| `bgmv_shrink_kernel` | Out-of-bounds atomic write | plain SIGABRT, asan | The output is sized from `lora_a_weights.size(1)` before four-dimensional weights are squeezed. With the documented 4D layout the output has one column and the kernel writes 16. The file's own import-time self-test triggers it. |
| `quantize_kv_transform` | Uninitialized output | perturb, poison | Destinations come from `torch.randint` and the output is `torch.empty`. |
| `vector_addition_custom` | Uninitialized output, 99.9% unwritten | perturb, poison | The kernel writes `a.size(0)` elements. The benchmark's own test passes 1024 by 1024 inputs, so 1,024 of 1,048,576 elements are written. The torch reference is documented as matching this and also returns `torch.empty_like`. |
| `attn_fwd_causal` | Uninitialized output, 25% unwritten | perturb, poison | The store mask keeps the first 96 of 128 head-dimension columns of a `torch.empty_like` output. |
| `argmax`, `masked_select`, `mean_reduction` | Not a bug | asan, tilelens, plain | Interpreter artifact. Each kernel combines masks with Python `and`. See section 4. The three ops are clean in run 43387358992 after the fix. |
| `chunked_cumsum_fwd` | Untriaged | tilelens only | No concrete detector agrees. |

**Result:** seven new confirmed memory-safety bugs in reference kernels of a benchmark commit that had already been fixed once. Four are out-of-bounds accesses and three return uninitialized memory. None has been reported upstream.

Twenty-one ops did not run on CPU in that sweep. The causes were interpreter restrictions on `tl.arange` arguments and on helper functions without `@triton.jit`, two remaining CUDA calls, and test signatures the adapter does not build.

## 3. Pilot on accepted Dr. Kernel kernels

**Population:** the corpus has 35,680 rounds with recorded feedback and 21,956 accepted rounds. One best-round kernel per trajectory gives 6,230 kernels that compiled, passed five of five correctness trials and were not decoys.

**Sample:** 300 kernels drawn with seed 20261113. Run 43374065442 audited them at the benchmark's shape and at batch size 3, with the first autotune config.

| Measure | Value |
|---|---|
| Auditable on the CPU interpreter | 298 of 300 |
| Flagged by any detector | 8 of 298 |
| Confirmed after triage | 3 of 298, which is 1.0% with a 95% interval of 0.3% to 2.9% |
| Confirmed out-of-bounds accesses | 0 of 298 |
| asan flags | 0 of 298 |

| Kernel | Speedup | Verdict | Evidence |
|---|---|---|---|
| `7520_r1` | 0.96 | Uninitialized output | A fused conv1d, bias and `tril` kernel stores with the triangular mask into a `torch.empty` output. 224,768 of 258,048 output elements, 87.1%, are never written. The result is correct only when that memory happens to be zero. |
| `1918_r2` | 0.88 | Uninitialized output | Three of four autotune configs leave most of a `torch.empty` output unwritten. The poison count is 87.5% under the first config and 75% under the second. |
| `4191_r4` | 4.82 | Uninitialized output and wrong axis | For `dim=0` the wrapper launches 64 programs for a 128-element `torch.empty` output, so half is never written. The written half reduces along the wrong axis. The task rounds a standard deviation of normal samples, so every expected value is 1.0. |
| `1887_r2`, `1926_r4`, `4636_r4` | | False positive | tilelens only. The flagged load sits behind a runtime `if` on the program id or behind a pointer chosen with `tl.where`. |
| `8302_r1`, `4526_r1` | | False positive | The reference builds its inputs at import time, before the seed was set. The harness now seeds first. |

All three confirmed kernels passed five of five KernelGYM correctness trials.
How `4191_r4` passed on a GPU is not established. The likely explanation is
that `torch.empty` returned a cached block that still held an earlier result,
and this needs a GPU run to confirm.

## 4. What the method work showed

1. **ASan on the interpreter is the reliable out-of-bounds oracle.** It found 13 of 13 known bugs and every one of its flags that was triaged was a real access.
2. **Atomic operations were invisible to it.** The interpreter writes atomics through raw pointers. The target now loads the same addresses first. This turned the `bgmv_shrink_kernel` heap corruption into an ASan report.
3. **A poison fill gives an exact oracle for unwritten outputs.** It reports the unwritten fraction and does not depend on heap contents.
4. **The interpreter and the compiler disagree on `and` and `or`.** The compiler makes them elementwise on tensors. The interpreter treats any non-scalar tensor as true, so `row_mask and col_mask` loses the row mask. Three sweep flags came from this alone. The source rewriter is patched to follow the compiler.
5. **The symbolic sanitizer is not reliable on model-written kernels.** All three of its solo flags in the pilot were false positives.

## 5. Reading against the December plan

The plan set a go threshold of 6 confirmed kernels in 200, which is 3%. The
pilot shows 1.0% with an upper bound of 2.9%, and no out-of-bounds access. By
the plan's own rule this is the narrow case and not the go case.

The evidence supports a different headline than the one planned.

1. Accepted generated kernels rarely access memory out of bounds in this corpus.
2. About one in a hundred returns uninitialized memory and still passes the benchmark.
3. Hand-ported benchmark references are worse. Seven of 101 runnable TritonGym references have a memory-safety bug after the maintainers' fix.
4. Checking either claim needs detector fixes that no published harness has.
