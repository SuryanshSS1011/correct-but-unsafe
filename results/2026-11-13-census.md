# Census of accepted Dr. Kernel kernels, 13 November 2026

This file extends `2026-11-13.md`. The census is run 43387362408. It audits the
whole accepted population with the `plain`, `asan` and `poison` detectors at the
benchmark's own input shape, under up to four autotune configs per kernel.

**Status:** 17 of 20 shards had finished when this was written. Shards 5, 7 and 16 were still running. The numbers below cover 5,295 of 6,230 kernels and will change slightly.

## 2. Triage

Thirteen of the 29 were confirmed by reading the source. The other 16 show the
same quantitative signature as a confirmed case and were not read one by one.
Labels are in `triage-census-partial.json`.

**Out-of-bounds reads, all three read:**

1. `6135_r2` runs a fixed-iteration binary search and loads `buckets[mid]` without a mask. A lane that has converged at the end loads one element past the 10-element table. ASan reports a 4-byte read at offset 0 after a 40-byte region.
2. `825_r3` and `160_r2` are fused linear layers. The input tile is masked on the reduction axis only. Under autotune configs whose `BLOCK_M` exceeds the batch size, rows past the end of the input are read. ASan reports reads directly after the 65,536-byte and 32,768-byte inputs.

**Uninitialized outputs, three root causes:**

1. **A fixed launch grid with an autotuned block size.** The wrapper computes the grid once, for example `triton.cdiv(n, 1024)`, and the kernel is autotuned over block sizes such as 256 and 512. A config with a smaller block writes a quarter or half of the output. The source comments show the misconception, for example "initial grid; autotune will adjust". Twenty of the 26 depend on the autotune config, and every one of those that was read has this cause.
2. **A store masked by a validity mask.** The kernel stores only where the value is non-zero by construction, such as inside the padded region of an unfold or below the diagonal of a `tril`. The zero positions of a `torch.empty` output are never written. `7520_r1`, `7962_r1` and `6852_r1` fall here.
3. **A wrong launch grid.** `4191_r4` launches 64 programs for 128 outputs.

**False positive:** `4089_r4`. The benchmark's own input is `torch.empty`. The detector now subtracts pattern that was present before the kernel ran.

## 3. Why these kernels pass the benchmark

KernelGYM draws fresh inputs for each of its five trials and compares the whole
output, so the pass needs an explanation. Two mechanisms fit the evidence.

1. **Autotuning hides a partial write on the first call.** On the first call the Triton autotuner benchmarks every config on the real arguments, so every config writes into the same output buffer and the buffer ends up complete. Later calls run only the cached winner. The kernel is then correct or not depending on which config won a timing race. An accepted kernel is one where a covering config won on that machine. 22 of the 29 defects appear only under some configs.
2. **The unwritten values do not depend on the input.** Where the expected value in the unwritten region is zero or a constant, fresh memory or a block freed by an earlier trial supplies it.

Both are inferences from source and from CPU runs. Neither has been observed on a GPU.

## 4. Repeat pilot with nearby shapes

Run 43382554518 repeated the 300-kernel pilot with every autotune config, the
poison detector and nearby shapes. It predates the boolean-operator fix.

1. A concrete detector flagged 5 of 298 kernels, which is 1.7% with an interval of 0.7% to 3.9%. Three are the kernels confirmed earlier. Two more, `3964_r4` and `6912_r4`, are flagged only when a shape constant is increased by one.
2. The symbolic detector alone flagged 4 kernels. Three are the known false positives and one is new and untriaged.
3. At nearby shapes, 12 of 298 kernels were silently wrong or crashed. These are untriaged. Some may be specialisation to the benchmark's constants and not memory errors.

## 5. Final TritonGym sweep

Run 43387358992 used the final code and covered 137 reference ops, of which 114
ran. All seven confirmed bugs were flagged again by a concrete detector. The
three boolean-operator artifacts were clean. Two ops, `chunked_cumsum_fwd` and
`kcache_copy`, were flagged by the symbolic detector alone and are untriaged.

## 6. Reading

1. The population rate is about 0.6%, which is lower than the pilot's point estimate and inside its interval.
2. Generated kernels in this corpus almost never read out of bounds. The three that do are textbook cases.
3. The dominant defect is a partially written output, and most of those depend on the autotune config. A harness that checks outputs after a single tuned call cannot see it.
4. A check that would catch all 26 costs little. It fills fresh allocations with a pattern and runs each autotune config separately.
